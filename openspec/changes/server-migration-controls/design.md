# Design

## Context
Существующий реестр поддерживает только GET/POST/PATCH. Новые routes по контракту backend 2026-11-02 пока не реализованы. Отсутствие routing не равно пустой успешной конфигурации.

## Goals / Non-Goals
Подготовить admin UI по контракту, сохранив старый реестр. Не выполнять реальную миграцию, установку VPN или отзыв в этой задаче.

## Decisions
- Реализация в features/manage-vpn-servers: model Zod DTO/намерений, api injectEndpoints, ui карточек/операций. Виджет шапки уже обеспечивает admin-only монтаж. FSD-зависимости только вниз к shared/api.
- Routing проверяется при открытии. 404/невалидный DTO/features=false блокируют соответствующие новые действия; legacy POST-форма сохраняется без изменений.
- Новая форма поддерживает nullable discovery metadata, fingerprint или полный ключ. Одноразовый мост пароля не меняется.
- Нативные RTK Query hooks: polling 2s только queued/running, скрытая вкладка — 15s, refetchOnFocus. needs_input и terminal останавливают polling. GET ошибок не меняет status операции.
- Операции и items читаются отдельно и постранично. UI считает created/reused/already_selected только по загруженным items.
- Отдельные prepare/resume/switch/revoke/retry команды с Idempotency-Key. Неизвестный результат сохраняет исходный payload/key; повтор только явным действием. Безопасное sessionStorage scoped по actor, очищается logout/сменой пользователя. Там нет паролей и произвольных SSH-команд.
- Переключение — без обязательного подтверждения; отзыв — отдельный confirmation. Никогда не отправлять отзыв из switch. Обновлять routing после конфликтов/завершения, не подменять revision и не повторять автоматически.
- Мобильный UI — вертикальные карточки, форма с одной колонкой и переносами; desktop — широкие карточки в существующем Dialog. Дизайн остального кабинета сохраняется.

## Risks / Trade-offs
- Недоступные новые API → явное сообщение о неподдерживаемой версии backend, старый CRUD доступен.
- Потерянный 202 → сохранение намерения до POST, восстановление без автозапуска.
- Partial не откатывает default/успешные элементы → читать routing, показать частичный результат и retry по backend.
- Изменение пароля не сохраняет его в actions/state/storage; ошибки отображаются только через безопасные коды.
