## Purpose
Предоставляет администратору безопасное управление подготовкой VPN-сервера, переключением выдач между серверами и отдельным явным отзывом с наблюдением асинхронных результатов.

## ADDED Requirements

### Requirement: Совместимость и доступ
UI SHALL быть доступен только admin и проверять routing/features до новых действий, сохраняя существующий CRUD на старом backend.
#### Scenario: Старый backend
- **WHEN** routing возвращает 404
- **THEN** UI показывает «Переключение серверов пока недоступно в этой версии backend», не запускает новые действия и сохраняет доступ к реестру.
#### Scenario: Адаптивность
- **WHEN** admin открывает экран на телефоне или desktop
- **THEN** формы и прогресс читаемы, кнопки доступны без горизонтального скролла.

### Requirement: Подготовка
UI SHALL запускать prepare и показывать шаги, а при needs_input отправлять только явный выбор из полученных кандидатов. Новая форма SHALL включаться только при поддержке нового контракта.
#### Scenario: Discovery
- **WHEN** операция требует candidate_id/udp_port/public_host
- **THEN** UI предлагает только обнаруженные кандидаты и порты, не угадывает выбор и не исполняет произвольные команды.

### Requirement: Переключение и отдельный отзыв
UI SHALL одной командой переключать выдачи на ready target без выбора source или автоматического отзыва. Отзыв SHALL требовать отдельного подтверждения области и сервера.
#### Scenario: Возврат
- **WHEN** переключение B→A возвращает reused
- **THEN** UI показывает повторное использование выдач и не утверждает, что ключи перевыпущены или B отозван.
#### Scenario: Файлы и устройства
- **WHEN** admin запускает switch
- **THEN** UI поясняет сохранение старых конфигов и необходимость скачать/импортировать актуальный файл; он не утверждает факт подключения устройств.
#### Scenario: Отзыв используемого сервера
- **WHEN** backend возвращает server_in_use
- **THEN** UI предлагает сначала переключить пользователей и не переключает их автоматически.

### Requirement: Операции и безопасные повторы
UI SHALL считать 202 только принятием, опрашивать queued/running, останавливать polling при needs_input/terminal и читать результаты постранично. Неизвестный исход SHALL сохранять тот же key/payload без автоматического POST после перезагрузки.
#### Scenario: Частичный результат
- **WHEN** status=partial/failed
- **THEN** успешные элементы не объявляются откатанными; retry доступен только при retryable, текущий default читается из routing.
#### Scenario: Таймаут статуса
- **WHEN** GET статуса завершается сетевой ошибкой или 503
- **THEN** операция не объявляется failed, доступно повторное чтение статуса.
#### Scenario: Восстановление
- **WHEN** страница обновлена после потерянного 202
- **THEN** исходный key/payload доступен для явного повтора, смена пользователя/logout очищает сохранённое намерение.

### Requirement: Защита данных и глобальное удаление
UI MUST NOT сохранять пароль в Redux/storage/URL/логах, показывать сырой SSH output или использовать глобальное удаление как очистку switch.
#### Scenario: Глобальное отключение
- **WHEN** admin подтверждает удаление пользовательских конфигов
- **THEN** предупреждение явно сообщает об отзыве доступа на всех серверах.
