# Spec Delta

## Purpose
Дать администратору доступное на телефоне и компьютере окно управления выдачами конфигов с безопасным повтором и отслеживанием результата.

## ADDED Requirements

### Requirement: Выдача новых конфигов
Окно SHALL валидировать целое count от 1 до 20, отправлять запрос через хук RTK Query с Idempotency-Key и показывать подтверждённый результат отдельно от принятия.

#### Scenario: Выдача
- **WHEN** admin отправляет допустимое число
- **THEN** POST передаёт count и ключ; после 202 запрашивается статус операции

#### Scenario: Неверное число
- **WHEN** введено нецелое число или значение вне 1..20
- **THEN** поле показывает ошибку и запрос не выполняется

### Requirement: Отзыв конфигов
Окно SHALL предоставлять отзыв одного, выбранных или всех конфигов после явного подтверждения, не обещая отключение до серверного подтверждения.

#### Scenario: Подтверждение
- **WHEN** admin выбирает отзыв
- **THEN** до подтверждения запрос не выполняется, после него используется соответствующий метод API

### Requirement: Результат и повтор
Окно SHALL отображать pending/running/succeeded/partial/failed, результаты элементов и ошибки. Повтор неизвестного или частичного результата MUST сохранять ключ и payload исходного запроса.

#### Scenario: Частичный успех
- **WHEN** сервер возвращает partial
- **THEN** показываются выполненные и неподтверждённые элементы, доступен повтор прежнего запроса

#### Scenario: Ошибка сети
- **WHEN** ответ mutation потерян
- **THEN** результат не считается успешным, повтор сохраняет прежний ключ
