# Design

## Context

См. proposal.md. Контракт проверен по backend vpn-server-registry/design.md, domain/server.go, application/servers.go и transport/http/servers.go обоих сервисов. Реализованы GET/POST/PATCH; PUT/default существует только в плане vpn-server-migration.

## Goals / Non-Goals

Управлять записями реестра через существующую admin-сессию. Не выполнять миграцию, SSH-проверку или установку VPN.

## Decisions

- FSD: widgets/site-header импортирует публичный API features/manage-vpn-servers. Feature содержит ui/model/api и зависит только от shared/api; новый entity не нужен до переиспользования.
- Мобильная кнопка со значком сервера рядом с бургером, desktop — кнопка с текстом. Dialog на узком экране с отступом 8px, одна колонка; на desktop две колонки полей, maxWidth md.
- GET списка при открытии, GET записи перед редактированием, POST для новой и PATCH только изменённых полей + expected_revision. RTK Query hooks с no-store и очисткой кеша после закрытия.
- Zod проверяет DTO и форму: host:port, идентификаторы, полный ED25519 public key, ограничения в байтах. Пустой пароль при редактировании не отправляется.
- Пароль остаётся в состоянии формы. Одноразовое локальное хранилище передаёт тело queryFn по непрозрачному request ID, удаляемому до сетевого запроса. Таким образом mutation args/state/actions не содержат пароль; queryFn не возвращает request/response meta. Стандартный body в аргументах мутации отвергнут из-за сохранения originalArgs в Redux.
- Во время сохранения нельзя закрыть форму или отправить повторно. После завершения пароль очищается. При сетевой неопределённости автоматического повтора POST нет: пользователь сначала обновляет список. После 409 форма блокирует сохранение до явной загрузки актуальной записи; ввод не перезаписывается фоновым GET.
- Ошибки 400/401/403/404/409/503 и сети имеют фиксированные сообщения, произвольные server error body не отображаются. Статусы успеха не обещают готовность рабочего сервера.

## Risks / Trade-offs

- Недоступность сети после POST не доказывает отсутствие записи → предложить обновление списка перед повторным созданием.
- Пароль проходит браузер для отправки backend, но не сохраняется в Redux/storage/логах. Сессия и шифрование остаются backend.
- PUT/default пока отсутствует → не показывать неработающую кнопку активации.
