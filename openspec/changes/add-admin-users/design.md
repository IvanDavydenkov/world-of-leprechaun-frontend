# Design

## Context
GET /admin/users?limit=50&after=ID возвращает массив {id, display_name, role}. Сортировка backend по ID, total и next cursor отсутствуют. Сервер проверяет сессию и роль.

## Goals / Non-Goals
Показать фактические данные каталога и подготовить VPN-сводку под backend-план admin-user-overview. Не добавлять управление пользователями и конфигами или выдуманные показания.

## Decisions
- entities/user добавляет Zod-схему и RTK Query hook через shared baseApi. Не копировать серверные записи в Redux slices.
- app/admin-guard проверяет текущую роль; ordinary user видит отказ, гостя обрабатывает session guard. Header показывает admin-пункт в desktop и мобильном меню.
- pages/admin-users содержит таблицу с переносом длинных ID, компактными ячейками на телефонах и полными значениями без горизонтального скролла страницы.
- Пагинация по 50 записей: хранится только история cursors. Next доступен при полной странице, последняя полная страница может вести на пустую; доступен возврат назад. Переключение использует currentData, чтобы не показывать предыдущую страницу под новым номером.
- 401 возвращает на вход после перепроверки сессии; 403 скрывает данные и показывает отказ. Сеть, 5xx, ошибочный DTO — сообщение и повтор. Кеш удаляется при уходе со страницы и logout, не persistится.
- /admin/users является API URL; React route /admin/users конфликтует с same-origin proxy, поэтому UI route — /admin/users-list. Прокси ограничен точным /admin/users, чтобы прямое открытие страницы работало.

## Risks / Trade-offs
- API не сообщает total → показывать только номер страницы и число отображённых записей.
- Опциональное vpn валидируется по черновому контракту admin-user-overview в соседнем backend. Старый ответ поддерживается, undefined/null отображается как «Нет данных», а не ноль. Бэкенд ещё реализуется в другом чате.
- Колонки: пользователь (имя/ID/роль), конфиги (total/active/disabled/pending), трафик (total/upload/download). Кнопка подробностей раскрывает профиль, даты наблюдения и список конфигов с состояниями, происхождением и наличием файла.
- freshness=stale сохраняет известные байты с предупреждением; unavailable скрывает показания; coverage=partial/unknown помечает неполную историю.
- При наличии X-Next-Cursor используется этот cursor. Без него новый ответ с vpn считается последней страницей; для старого DTO остаётся fallback полной страницы. Смена страниц не смешивает записи.
- Старые admin-права могут исчезнуть → session polling/focus и серверный 403 закрывают содержимое.
