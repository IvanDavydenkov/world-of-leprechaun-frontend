# Spec Delta

## Purpose
Предоставить вход через существующую авторизацию Яндекса и безопасный доступ пользователя к кабинету с обработкой отказов и ошибок сессии.

## ADDED Requirements

### Requirement: Проверка сессии
Frontend SHALL проверять серверную сессию перед отображением кабинета через хук RTK Query, без сохранения токенов в браузерном хранилище.

#### Scenario: Действующая сессия
- **WHEN** /me возвращает корректный профиль
- **THEN** пользователь видит кабинет и своё имя

#### Scenario: Гость или истечение
- **WHEN** /me возвращает 401
- **THEN** открывается страница входа и приватное содержимое не отображается

#### Scenario: Ошибка сервиса
- **WHEN** проверка профиля завершается ошибкой сети, 5xx или некорректным ответом
- **THEN** видна ошибка с повторной попыткой, кабинет скрыт

### Requirement: Вход и прерывание
Frontend SHALL предоставлять доступную кнопку входа через Яндекс на телефоне и desktop и понятное сообщение при неуспешном возврате OAuth.

#### Scenario: Успешный вход
- **WHEN** backend успешно завершает callback
- **THEN** браузер возвращается в кабинет с проверкой сессии

#### Scenario: Отказ или ошибка callback
- **WHEN** callback или запуск OAuth возвращает HTTP-ошибку
- **THEN** пользователь возвращается на страницу входа с сообщением и возможностью повторить

#### Scenario: Пользователь закрыл вкладку
- **WHEN** пользователь прервал OAuth и позднее открывает кабинет
- **THEN** frontend заново проверяет сессию, не предполагая успеха

### Requirement: Выход
Frontend SHALL выполнять выход через RTK Query mutation и очищать кеш после подтверждённого сервером выхода.

#### Scenario: Успех выхода
- **WHEN** сервер успешно обрабатывает выход
- **THEN** отображается вход, приватный кеш очищен

#### Scenario: Ошибка выхода
- **WHEN** выход завершается ошибкой
- **THEN** показывается сообщение и доступна повторная попытка
